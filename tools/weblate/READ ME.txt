WARPFORGE REVIVAL - WEBLATE (the translation site), self-hosted
===============================================================

Weblate is where players translate the mod, the website, the guides and the Patcher app. It reads the
translation files from the mod repo on GitHub (wf-revival-mod, folder localization/) and writes the
approved translations back to a branch called "weblate". From there they are merged and copied to the game
server when you say so.

This folder:
  docker-compose.yml, environment   Weblate's own files (unchanged, from github.com/WeblateOrg/docker-compose)
  docker-compose.override.yml       our changes: the local port, the Caddy network, our settings file
  weblate.env                       our settings - FILL IN THE CHANGE-ME LINES. Private: it holds passwords.
  1 - start weblate.bat             starts it (Docker Desktop must be running)
  2 - stop weblate.bat              stops it (nothing is lost)
  3 - update weblate.bat            newest version, keeps everything
  4 - show weblate log.bat          what it is doing, when something is wrong


FIRST SETUP
-----------
1. Install Docker Desktop for Windows (it sets up WSL 2 itself). Start it once.

2. Open weblate.env in Notepad and fill in every CHANGE-ME:
     - WEBLATE_ADMIN_EMAIL / WEBLATE_ADMIN_PASSWORD: your admin login.
     - the e-mail lines: an SMTP server for sign-up mails (port 587, TLS). A Gmail account with an
       "app password" works. Without e-mail, set WEBLATE_REGISTRATION_OPEN=0 and invite people yourself.
     - POSTGRES_PASSWORD: any long random text (you never type it again).
   If you use another address than wf-translate.silentanarchist.com, change it in the three lines that
   name it.

3. Run "1 - start weblate.bat". The first start takes a few minutes. Then open http://127.0.0.1:8090 on this
   computer and sign in with the admin account.

4. Public address through Caddy (your Caddy container: host ports 443 and 80 go to 8443 and 8081 inside it).
   a) DNS: an A record for wf-translate.silentanarchist.com to the same public IP as the game site.
   b) Put Caddy on the shared network "wf-proxy" (the start batch creates it). In Caddy's docker-compose.yml:
          services:
            caddy:
              networks:
                - default
                - wf-proxy
          networks:
            wf-proxy:
              external: true
      (or once, without editing:  docker network connect wf-proxy <name of the caddy container> )
   c) Add to the Caddyfile:
          wf-translate.silentanarchist.com {
              reverse_proxy wf-weblate:8080
          }
      Caddy fetches the HTTPS certificate itself. Because it listens on 8443/8081 inside the container, its
      Caddyfile needs (probably has already) at the top:
          {
              http_port  8081
              https_port 8443
          }
   d) Reload Caddy:  docker exec <caddy container> caddy reload --config /etc/caddy/Caddyfile
      Then https://wf-translate.silentanarchist.com shows Weblate.
   Weblate itself is not opened to the internet: only Caddy reaches it, over wf-proxy.


CONNECT GITHUB
--------------
5. In Weblate: your admin menu > Manage > SSH keys. Under "Add host key" enter github.com (port empty) and
   submit, so Weblate trusts GitHub. Then "Generate Ed25519 SSH key" (if none is shown) and copy the
   public key.
6. On GitHub: wf-revival-mod > Settings > Deploy keys > Add deploy key: paste it, tick "Allow write
   access". (Only this repo; Weblate never gets your account.)


THE PROJECT AND ITS COMPONENTS
------------------------------
7. Add a project: name "Warpforge Revival", URL slug "warpforge-revival".

8. Add one component for each area (Add new translation component > From version control). Same for all:
     Version control system:  Git
     Source code repository:  git@github.com:silentanarchist/wf-revival-mod.git
     Repository branch:       main
     Repository push URL:     git@github.com:silentanarchist/wf-revival-mod.git
     Push branch:             weblate
     File format:             JSON file
     Monolingual base language file / Template for new translations: the en.json below
     Edit base file:          OFF   (the English comes from the code)
     Language filter:         ^(?!en$)[^.]+$
   and per component:
     Name          File mask                          Base file
     Mod           localization/mod/*.json            localization/mod/en.json
     Website       localization/site/*.json           localization/site/en.json
     Guides        localization/guides/*.json         localization/guides/en.json
     Patcher       localization/patcher/*.json        localization/patcher/en.json   (once the patcher
                                                       translations are merged into main)
   For the 2nd component on, "Source code repository" can be  weblate://warpforge-revival/mod  (shares one copy).

9. Mark the machine drafts as drafts, in each component: Tools > Bulk edit, search  state:translated ,
   new state "Needs editing". Translators then see every draft as something to check.

10. Texts with {name} in braces: after the component is made, Operations > Settings > Translation > "Translation flags": add
      placeholders:r"\{\w+\}"
    so Weblate warns when a translation loses or changes one. For Website and Guides also add  safe-html
    (they may hold <strong>, <code>, <a> and nothing else).


TRANSLATORS
-----------
- Give each community editor their language: Manage > Users / Teams (per-language "Translate" or "Review").
- Turn on reviews (Project settings > Workflow > "Enable reviews") if you want a reviewer to approve changes.


GETTING TRANSLATIONS INTO THE GAME
----------------------------------
Weblate commits to the "weblate" branch. Tell Claude to pull translations: it merges them into main, checks
them and copies them to the server (W:\content\files\localization). Nothing reaches players before that.
Later this can run by itself.


BACKUPS
-------
Translations also live in the GitHub repo, but accounts, reviews and history are only in Weblate:
Manage > Backups can save them regularly (to a folder or a backup service).
